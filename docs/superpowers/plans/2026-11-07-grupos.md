# Grupos: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** grupos de amigos cifrados de extremo a extremo, con administradores que cambian el nombre y la foto. La interfaz es la de la maqueta aprobada.

**Arquitectura:**
- **Prosody:** un componente de salas (`groups.<dominio>`) y un módulo propio, `mod_palique_groups`. El módulo se encarga de lo que Prosody no hace solo: salir, el relevo del último administrador, la lista de miembros con nombre y antigüedad, y los avisos del grupo como mensajes de la sala, que se archivan.
- **App:** un módulo nuevo, `src/main/groups.ts`, habla el XMPP de las salas sobre la conexión de `xmpp.ts` y cifra con el mismo `omemo.ts`. `index.ts` trata cada grupo como una conversación más: misma ventana, misma memoria de sesión, mismos no leídos.

**Tecnología:**
- Prosody 13: `muc`, `muc_mam`, la foto de sala de `muc/vcard.lib.lua` y Lua para el módulo.
- XEP-0045, XEP-0313, XEP-0402 (marcadores), XEP-0249 / invitaciones mediadas, OMEMO 0.3 sobre `groupchat`.

**Especificación:** [docs/superpowers/specs/2026-11-07-grupos-design.md](../specs/2026-11-07-grupos-design.md). La interfaz es la de la maqueta <https://claude.ai/artifact/CF8QkuxpnKLmf73sRhoHTU>.

## Decisiones sobre la especificación (tras mirar Prosody 13)

- **«Admin» en Palique = afiliación `owner` de XMPP**, de la que puede haber varias.
  - En Prosody solo el propietario cambia la configuración (nombre) y la foto de sala (vCard).
  - Los propietarios pueden nombrar y quitar a otros propietarios, y quitar a cualquiera.
  - La afiliación `admin` de XMPP no se usa.
- **Foto del grupo:** la vCard de la sala (`vcard-temp`, que ya trae Prosody) y no un módulo propio. Sin foto, el mosaico de caras.
- **Salir y relevo, en `mod_palique_groups`:** Prosody no deja a un miembro quitarse a sí mismo ni al último propietario bajarse.
- **Nombres de quien no es contacto:** el módulo guarda el nombre visible de cada miembro en los datos de su afiliación al entrar (`<nick>` en su presencia). Así la lista de miembros y los avisos tienen nombre aunque esa persona esté desconectada.
- **Avisos del grupo generados por el servidor:** el módulo los publica en la sala como mensajes `groupchat` con `<event xmlns='urn:palique:groups:0' …/>`. Quedan en el archivo y los recibe también quien estaba desconectado. La app no los deduce.
- **Apodo de sala = localparte de la dirección interna** (la especificación). De ahí sale el JID real de quien escribe, también en lo archivado.

## Restricciones globales

- **Componente:** `groups.<dominio>`, con `restrict_room_creation = "local"` y estos valores por defecto:
  - `muc_room_default_public = false`
  - `muc_room_default_members_only = true`
  - `muc_room_default_persistent = true`
  - `muc_room_default_public_jids = true`
  - `muc_room_default_allow_member_invites = true`
  - `muc_room_default_change_subject = false`
  - `muc_room_default_history_length = 0`
  - `muc_log_by_default = true`
  - `muc_log_expires_after = "1w"`
- **Espacio propio:** `urn:palique:groups:0`.
  - `<leave/>` (iq set a la sala);
  - `<members/>` (iq get a la sala) → `<member jid affiliation='owner|member' name since/>`;
  - `<event kind='created|added|left|removed|name|photo|owner|unowner' actor jid name/>` en mensajes de sala.
- **Nombre del grupo:** de 1 a 40 caracteres.
- **Grupos de hasta 50 personas.** El 51.º no se añade y la app muestra un error.
- **Marcadores:** nodo PEP `urn:xmpp:bookmarks:1`, un ítem por sala (id = JID de la sala), `<conference xmlns='urn:xmpp:bookmarks:1' autojoin='true' name='…'><nick>…</nick></conference>`, publicado con `pubsub#access_model = whitelist` y `pubsub#persist_items = true`.
- **Invitaciones:** se aceptan solas solo si quien invita es contacto tuyo (filtro de desconocidos); si no, se ignoran.
- **Mensajes de grupo:**
  - cifrados con OMEMO para todos los dispositivos de todos los miembros salvo este;
  - guiños sí, zumbido no;
  - `<body>` de reserva «Mensaje cifrado con OMEMO».
- **Textos de la maqueta, literales:**
  - «Nuevo grupo…», «+ Nuevo», «Grupos ({n})», «Nombre del grupo», «¿A quién invitas?», «Crear grupo»;
  - «Cada uno podrá añadir a sus amigos.», «Miembros», «{n} personas», «Admin»;
  - «Tu contacto», «No es tu contacto», «Añadir como contacto», «Petición enviada»;
  - «Añadir amigos», «Cambiar nombre y foto», «Salir del grupo», «Hacer administrador», «Quitar como administrador», «Quitar del grupo»;
  - «Nombre y foto del grupo», «Subir una imagen…», «Usar las caras de los miembros»;
  - «Todos tus contactos ya están en el grupo.», «Escribe un mensaje al grupo…».
  - Avisos: «{name} ha creado el grupo», «{actor} ha añadido a {name}», «{name} ha salido del grupo», «{actor} ha quitado a {name} del grupo», «{actor} ha cambiado el nombre a «{name}»», «{actor} ha cambiado la foto del grupo», «{actor} ha hecho administrador a {name}», «{actor} ha quitado a {name} como administrador», «Te han quitado de «{name}»». Con «Has…» cuando el actor eres tú.
- Nunca se muestran correos ni direcciones internas; la búsqueda de la lista encuentra contactos y grupos.
- **XMPP:** `xmpp.ts` y el nuevo `groups.ts`. `xmpp.ts` exporta solo lo que `groups.ts` necesita, como API interna de main. AGENTS.md lo dice.
- Textos con `_()`; después, `check:i18n -- --write` y traducir con el skill.
- **No hacer commit ni push sin que el usuario lo pida.** Antes de cada commit: typecheck, lint y los checks afectados.

## Puntos a vigilar en la revisión

1. **Te quitan de un grupo mientras estás desconectado:** al iniciar sesión, la entrada a la sala falla (`registration-required` o `forbidden`). La app debe quitar el marcador, quitar el grupo de la lista y avisar «Te han quitado de «{name}»», sin reintentar en bucle (Tarea 3).
2. **Mensajes del archivo y en vivo a la vez al reconectar:** no deben salir duplicados. Se quitan duplicados por el `stanza-id` de la sala (Tarea 3).
3. **Se va el último administrador, o te vas siendo el único miembro:** en el primer caso pasa a serlo el miembro más antiguo; en el segundo la sala se destruye (Tarea 1).
4. **Invitación de alguien que no es tu contacto** (un amigo de un amigo te añade a través de un tercero): no se acepta sola ni se muestra (Tarea 3).
5. **Mensaje de un miembro cuyos dispositivos aún no conoces** (no es tu contacto y acaba de entrar): se piden su lista y su paquete, `seen()` antes de descifrar, y si no se puede, «No se ha podido descifrar este mensaje», sin excepción (Tarea 3).

```ts
export type Member = { jid: string; name: string; owner: boolean; contact: boolean; since: number }
export type Group = { jid: string; name: string; photo: string; members: Member[]; owner: boolean }
export type GroupEvent = {
  kind: 'created' | 'added' | 'left' | 'removed' | 'name' | 'photo' | 'owner' | 'unowner' | 'kicked'
  actor: string; actorName: string; jid: string; name: string
}
export function groups(): Group[]
export async function createGroup(name: string, members: string[]): Promise<string> // room jid
export async function addMembers(room: string, members: string[]): Promise<void> // contacts only
export async function removeMember(room: string, member: string): Promise<void> // owners
export async function setOwner(room: string, member: string, owner: boolean): Promise<void>
export async function setName(room: string, name: string): Promise<void>
export async function setPhoto(room: string, png: Uint8Array | null): Promise<void> // null = faces
export async function leaveGroup(room: string): Promise<void>
export async function sendGroupMessage(room: string, body: string): Promise<ChatMessage>
export async function sendGroupWink(room: string, wink: string): Promise<ChatMessage>
export function joinAll(): Promise<void> // from bookmarks, at every 'online'
```

- `ChatMessage` (`xmpp.ts`) gana `sender?: string` (JID real de quien escribe, en grupos), `senderName?: string` y `event?: GroupEvent`.
- Los mensajes y avisos de grupo salen por el mismo `onMessage` con `with = JID de la sala`. `Snapshot` gana `groups: Group[]`.
