# Cifrado de extremo a extremo (OMEMO): plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** que todas las conversaciones de dos vayan cifradas con OMEMO 0.3 y que nada de lo hablado se guarde en el ordenador.

**Arquitectura:**
- `src/main/omemo.ts` (nuevo) guarda las claves y las sesiones en `omemo.sqlite` y cifra y descifra con la librería de Signal. No sabe nada de XMPP.
- `src/main/xmpp.ts` publica y lee las listas de dispositivos y los paquetes en PEP, construye y lee el elemento `<encrypted>` y llama a `omemo.ts`.
- `src/main/index.ts` deja de guardar en disco: cada conversación vive en memoria durante la sesión.
- La interfaz muestra los avisos de cifrado y la verificación.

**Tecnología:**
- `@privacyresearch/libsignal-protocol-typescript@0.0.16` (GPL-3.0-only), fijada.
- `node:sqlite` y `node:crypto` (AES-128-GCM).
- `safeStorage` de Electron.

**Especificación:** [docs/superpowers/specs/2026-11-07-cifrado-design.md](../specs/2026-11-07-cifrado-design.md)

## Restricciones globales

- OMEMO 0.3, espacio `eu.siacs.conversations.axolotl`:
  - nodos PEP `eu.siacs.conversations.axolotl.devicelist` (ítem `current`) y `eu.siacs.conversations.axolotl.bundles:<deviceId>`;
  - publicados con `pubsub#access_model = open`.
- Número de dispositivo: aleatorio de 31 bits, estable por cuenta y por instalación.
- 100 claves de un solo uso; se reponen hasta 100 al bajar de 25.
- Clave firmada renovada cada 30 días; la anterior se conserva otros 30.
- Carga: AES-128-GCM, clave e IV aleatorios (IV de 12 bytes al enviar; aceptar 12 o 16 al recibir).
  - `<payload>` = texto cifrado sin etiqueta.
  - Lo que va cifrado para cada dispositivo = clave (16) ‖ etiqueta (16).
- `<body>` de reserva: `_('Mensaje cifrado con OMEMO')`, más `<store xmlns='urn:xmpp:hints'/>`.
- Código de verificación: la clave pública de identidad sin el byte `0x05`, en hexadecimal minúsculas, en 8 grupos de 8 (el formato de Conversations).
- Textos fijados:
  - «Mensaje cifrado con OMEMO»;
  - «No se ha podido descifrar este mensaje»;
  - «Este mensaje no está cifrado»;
  - «{name} tiene que actualizar Palique para recibir mensajes cifrados»;
  - «{name} ha empezado a usar Palique en otro dispositivo»;
  - «La clave de cifrado de {name} ha cambiado»;
  - «Verificar cifrado…»;
  - «Marcar como verificado»;
  - «Aceptar la clave nueva».
- Nada de lo hablado se escribe en disco. En `palique.log` nunca hay texto de mensajes ni claves.
- Licencias: se admite GPL-3.0/AGPL-3.0 (AGENTS.md, Tarea 1).
- XMPP solo en `xmpp.ts`; IPC solo en `index.ts` y el preload; validar en main lo que llega del renderer.
- Textos con `_()`; después, `npm run check:i18n -- --write` y traducir siguiendo `agents/skills/translate/SKILL.md`.
- **No hacer commit ni push sin que el usuario lo pida.** Antes de cada commit: `npm run typecheck`, `npm run lint` y los checks afectados.

## Puntos a vigilar en la revisión

1. **Llega un mensaje normal de un dispositivo sin sesión** (el contacto reinstaló Palique): debe mostrarse «No se ha podido descifrar este mensaje», sin romper nada, y el siguiente envío debe rehacer la sesión con su paquete (Tarea 3).
2. **Copia de un mensaje propio enviado desde otro dispositivo nuestro, sin clave para este** (se envió antes de que existiera): se ignora en silencio, no se muestra como fallo (Tarea 3).
3. **Contacto con varios dispositivos y uno bloqueado** (verificado y con la clave cambiada): se envía a los demás y solo ese se queda fuera hasta aceptar (Tareas 2 y 3).
4. **Muchos mensajes con clave de un solo uso al iniciar sesión** (los guardados mientras estabas desconectado): el paquete se vuelve a publicar una vez tras la tanda, no una por mensaje (Tarea 3).
5. **Reinicio de la app:** mismo número de dispositivo, mismas sesiones y mismas claves. No se publica un dispositivo nuevo cada vez (Tarea 2).

```ts
export type Seal = { seal(data: Uint8Array): Uint8Array; open(data: Uint8Array): Uint8Array }
export type Device = { jid: string; deviceId: number }
export type Bundle = {
  deviceId: number
  identityKey: Uint8Array
  signedPreKey: { id: number; publicKey: Uint8Array; signature: Uint8Array }
  preKeys: { id: number; publicKey: Uint8Array }[]
}
export type Encrypted = {
  sid: number
  iv: Uint8Array
  keys: { rid: number; prekey: boolean; data: Uint8Array }[]
  payload: Uint8Array
}
export type TrustChange = { jid: string; deviceId: number; kind: 'new-device' | 'key-changed' }
export type DeviceTrust = { deviceId: number; fingerprint: string; verified: boolean; blocked: boolean }
export class OmemoError extends Error {
  code: 'no-key' | 'bad-message' | 'blocked'
}
export type Omemo = {
  deviceId: number
  bundle(): Promise<Bundle>
  needsRefill(): boolean // fewer than 25 one-time keys, or signed key older than 30 days
  refill(): Promise<void> // back to 100 one-time keys; rotates the signed key when due
  hasSession(to: Device): Promise<boolean>
  startSession(to: Device, bundle: Bundle): Promise<void>
  encrypt(text: string, to: Device[]): Promise<Encrypted> // blocked devices are skipped
  decrypt(from: string, message: Encrypted): Promise<string> // throws OmemoError
  seen(jid: string, deviceIds: number[]): TrustChange[] // new devices of a known contact
  takeChanges(): TrustChange[] // key changes noticed while decrypting/starting sessions
  devices(jid: string): DeviceTrust[]
  fingerprint(): string
  setVerified(to: Device, verified: boolean): void
  acceptKey(to: Device): void // unblocks a verified device whose key changed
  close(): void
}
export function openOmemo(file: string, account: string, seal?: Seal): Promise<Omemo>
export const fingerprintOf: (identityKey: Uint8Array) => string
```

- [ ] **Paso 1: `scripts/check-omemo.ts`, que debe fallar.** Dos dispositivos, A y B, con ficheros temporales y un `Seal` de prueba que invierte los bytes. Asserts:
  - **Sesión y envío:** `const b = await bob.bundle()`; `await alice.startSession({ jid: 'b@x', deviceId: bob.deviceId }, b)`; `const m = await alice.encrypt('hola', [{ jid: 'b@x', deviceId: bob.deviceId }])`; `m.keys[0].prekey === true`; `await bob.decrypt('a@x', m) === 'hola'`.
  - **La respuesta va sin clave de un solo uso:** `prekey === false` y Alice la descifra.
  - **Un mensaje no se descifra dos veces:** el segundo `bob.decrypt('a@x', m)` lanza `OmemoError`.
  - **La clave de un solo uso usada no vuelve:** su id ya no está en `(await bob.bundle()).preKeys`.
  - **Reposición:** tras consumir 76 claves, `needsRefill() === true`; tras `refill()`, el paquete vuelve a tener 100 y `needsRefill() === false`.
  - **Dispositivo nuevo:** `alice.seen('b@x', [bob.deviceId])` → `[]` la primera vez (primer contacto); con un segundo dispositivo de B, devuelve `[{ jid: 'b@x', deviceId: bob2.deviceId, kind: 'new-device' }]`.
  - **Cambio de clave:** se regenera B con el mismo `deviceId` y otra identidad. `startSession` con su paquete nuevo funciona y `takeChanges()` devuelve `kind: 'key-changed'`.
  - **Bloqueo:** con `setVerified` antes del cambio, `encrypt` excluye ese dispositivo y `devices('b@x')` lo marca `blocked`. Tras `acceptKey`, vuelve a incluirse.
  - **Carga manipulada:** cambiar un byte de `payload` hace que `decrypt` lance `OmemoError` con `code: 'bad-message'`.
  - **Persistencia** (punto a vigilar 5): cerrar y reabrir el fichero de A conserva `deviceId` y la sesión; `encrypt` funciona sin `startSession`.
  - **Cifrado en reposo:** el contenido en bruto de `omemo.sqlite` no contiene los bytes de la clave privada de identidad.
  - **Verificación:** `fingerprint()` tiene 71 caracteres (`/^([0-9a-f]{8} ){7}[0-9a-f]{8}$/`).
